## Context

The upstream Codex CLI uses Rust/tungstenite for Responses WebSocket
connections. codex-lb uses Python `websockets` for the same upstream
connection, which by default emits Python-library transport details such as
`Sec-WebSocket-Extensions: permessage-deflate; client_max_window_bits` and
library-managed persona headers.

## Goals / Non-Goals

**Goals:**

- Make account-bound Codex Responses WebSocket handshakes closer to the
  measured Codex CLI Rust/tungstenite shape.
- Preserve existing proxy selection, per-account TLS selection, timeout, frame
  size, and error mapping behavior.
- Keep the change covered by unit tests and local raw-handshake measurement.

**Non-Goals:**

- Replace the Python `websockets` transport.
- Guarantee byte-for-byte parity for the built-in Upgrade header order.
- Change downstream WebSocket API behavior or message framing.

## Decisions

- Disable WebSocket compression by passing `compression=None`.
  - Rationale: measured Rust/tungstenite handshakes do not offer
    `permessage-deflate`; Python `websockets` does by default.
  - Alternative considered: filter `Sec-WebSocket-Extensions` from inbound
    headers only. That does not affect the extension offer generated by the
    client library.

- Move `Origin` and `user-agent` into `additional_headers` and disable the
  library-managed `origin` / `user_agent_header` outputs.
  - Rationale: this lets codex-lb control the custom header block ordering and
    casing for the Codex persona headers.
  - Alternative considered: continue using the high-level parameters. That
    preserves semantics but leaves a more Python-specific raw handshake.

- Keep the existing `websockets` client.
  - Rationale: the remaining built-in header order mismatch is confined to
    `Upgrade`, `Connection`, `Sec-WebSocket-Key`, and
    `Sec-WebSocket-Version`. Eliminating it would require a custom handshake
    implementation or a different client library, which is a larger reliability
    risk.

## Risks / Trade-offs

- Built-in Upgrade header order still differs from Rust/tungstenite. Mitigation:
  capture and document the remaining mismatch; revisit only if this specific
  signal proves material.
- Disabling compression can increase upstream bandwidth for compressible
  frames. Mitigation: Codex request and event frames are already bounded by
  existing size limits, and parity with the Codex CLI handshake is the priority
  for this path.
